# Shared taxonomy

This repository uses a single taxonomy so all modules can be filtered, linked, and rolled up consistently.

## Risks

These are the four product-delivery risks used across tools, plays, experiments, and scorecards.

| Risk | Meaning |
| --- | --- |
| `value` | The team is solving a problem that matters and can create measurable benefit. |
| `usability` | The solution is understandable and usable by the intended audience. |
| `feasibility` | The team can build, ship, and operate the solution effectively. |
| `viability` | The solution works within business, operational, legal, and strategic constraints. |

## Scorecard dimensions

These five dimensions make the essay and scorecard operational.

| Dimension | Meaning |
| --- | --- |
| `shared-tooling` | Teams use common tools and reusable prompts or workflows instead of rebuilding from scratch. |
| `cross-functional-ownership` | Roles can move across traditional handoffs and help cover adjacent risks. |
| `experiment-velocity` | Teams can propose, run, and review experiments quickly. |
| `delivery-autonomy` | Teams can ship meaningful progress without waiting on long specialist queues. |
| `impact-learning` | Teams record outcomes and use them to improve later decisions. |

## Mapping guidance

### Risks

- Use `value` when an entry helps a team identify the right problem, audience, or outcome.
- Use `usability` when an entry improves clarity, validation, or customer understanding.
- Use `feasibility` when an entry removes technical, operational, or workflow bottlenecks.
- Use `viability` when an entry strengthens business fit, governance, or sustainability.

### Dimensions

- Use `shared-tooling` for reusable assets another team can adopt directly.
- Use `cross-functional-ownership` for plays that shift work across roles with clear guardrails.
- Use `experiment-velocity` for ideas that shorten the loop from hypothesis to review.
- Use `delivery-autonomy` for practices that reduce blocking dependencies and handoffs.
- Use `impact-learning` for notes, evidence, and scorecard movement that help the organisation learn.

## Tagging rules

1. Every tool, play, experiment, and scorecard must have at least one `risk`.
2. Every tool, play, experiment, and scorecard must have at least one `dimension`.
3. Prefer one to two primary risks unless a record clearly spans more.
4. Use the smallest honest set of tags; avoid tagging everything.
5. If a new concept does not fit, update this taxonomy deliberately rather than improvising local tags.
